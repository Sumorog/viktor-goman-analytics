## 1. Общие положения

### 1.1 Цель
Обеспечить передачу данных с носимых устройств (пульс, температура, SpO2, тревожная кнопка) в систему ЕМИАС для мониторинга пациентов 65+.

### 1.2 Ограничения
- Пилот: 500 устройств, 3 поликлиники ДЗМ
- Срок: 3 месяца (MVP) + 3 месяца (промышленная эксплуатация)
- Бюджет: [скрыто]

---

## 2. Архитектура

### 2.1 Протокол передачи
- REST API, JSON
- Частота: каждые 5 мин (обычный режим), каждые 30 сек (тревога)
- Таймаут: 10 сек

## 4. Коды ответа и сценарии ошибок

| HTTP | Код в теле | Действие клиента |
|------|------------|------------------|
| 400 | `VALIDATION_ERROR` | Исправить JSON по схеме, повторить запрос |
| 401 | `UNAUTHORIZED` | Обновить OAuth2-токен, проверить clock skew |
| 409 | `DUPLICATE_MEASUREMENT` | Идемпотентность: тот же `device_id`+`timestamp` уже принят |
| 422 | `PATIENT_NOT_LINKED` | Пациент не сопоставлён с ЕМИАС — эскалация в МИС |
| 503 | `EMIAS_UNAVAILABLE` | Экспоненциальный backoff, не чаще 1 запроса / 30 сек |

---

## 5. Безопасность и ПДн

- Транспорт: TLS 1.2+, pinning сертификата на стороне шлюза резидента (пилот).
- В логах интеграции — только псевдонимы устройств; `patient_id` не логировать в открытом виде.
- Хранение ключей API — в секрет-хранилище; ротация раз в 90 дней.

---

## 6. Критерии приёмки (выдержка)

1. **Пропускная способность:** не менее 500 устройств × 12 измерений/час в пике без деградации SLA приёма `< 2%` отказов по `503`.
2. **Тревога:** событие `panic_button` доставлено в очередь ЕМИАС ≤ 35 сек с момента нажатия (пилотная метрика).
3. **Согласованность:** 100% успешно принятых пакетов имеют запись в журнале аудита с `correlation_id`.
4. **Пилот с клиниками:** подписанные протоколы UAT от **5 поликлиник ДЗМ**; замечания закрыты в версии 1.3.
